活動頁 `https://maplestoryclassic-event.beanfun.com/EventAd/EventAd?eventAdId=19046` 是 Vue SPA，
真資料在：

```
GET https://maplestoryclassic-event.beanfun.com/api/EventAd/GetDetail?EventADID=19046
```

回傳 `data.event[0]`（標題／起訖）與 `data.topics[]`（`topicContent` 是 HTML 表格）。
機率表在 `topicName == "抽取機率說明"` 那一筆，`<tr>` 逐列解析，兩欄 = 道具名稱 / 機率。

## 設計定案

### 產品定位

- **體驗＋統計合一**：主體是抽卡，下方掛統計面板。
- **多期 pool 框架**：資料結構按「一期轉蛋 = 一個 pool」設計。目前只有 19046 一筆。
- **成本換算成新台幣**，依實際操作計價：單抽 20、10連/自動 18。頁面標注「依 1 點 = NT$1 換算」。

### 互動

- **三種操作**：單抽 / 10 連 / 自動模式。
- **無限抽，不做買券流程**。點了就抽，零摩擦。
- **連抽**：直接設「要抽幾次」（預設 100，另有 10/100/500 快捷鈕），旁邊即時顯示約略花費。
  **2026-08-20 修訂**：原本是「設預算上限、抽到達成目標或燒完預算為止」，使用者實測後
  認為太複雜，改成單純的次數。連帶拿掉預算概念；目標降級為純進度顯示，不再是停止條件。
  仍有 **10,000 抽安全煞車**（一個 session 的總上限）。
- **自動模式的播放**：計數器與金額**滾動快轉約 3~5 秒**，可中途喊停。
  不要瞬間出結果——讓人「感受到」700 抽的重量就是這個工具的重點。
- **翻卡動畫**：短暫遮蔽 → 翻開，用上表的機率階層映射稀有度顏色/光效。

### 目標系統

- 內建目標「**神秘任務**」為預設：`6 種橡皮擦(各1) AND (六角水晶項鍊 OR 水女神的衣料)`。
  獎勵內容欄位寫「**未公開**」（Q25=B 決定不挖客戶端 Quest 包）。
- 可自訂：**UI 只給「勾選道具＋設數量」**，資料模型支援 `AND of OR-groups`
  （神秘任務只是它的一個實例）。**UI 不暴露 OR**——沒有使用者會想組 OR。
- **純進度追蹤，不做任何機率預測**（見下方「已知取捨 1」）。

### 視覺

- **只有互動區做遊戲風**（遊戲視窗 + 轉蛋機 + 翻卡），統計面板/目標設定/機率表維持站內簡約風。
- 遊戲視窗**形似即可，不追求 1:1 還原**：抓住「視窗框 + 放射光背景 + 轉蛋機」三個關鍵印象，
  按鈕按實際需求排（遊戲原版只有一顆「使用」鈕，我們需要三種操作）。
- 截圖左下「剩餘數量」的位置 → 改顯示 **「已抽 N 次 ・ NT$X」**。
- **手機等比縮放**，功能全保留。因為 Q16 選了「形似即可」，responsive 是免費的。

### 版面（由上到下）

```
1. 遊戲視窗（轉蛋機 + 三顆操作鈕 + 已抽/花費）
2. 目標設定（預設神秘任務、可自訂、預算上限輸入）
3. 統計面板（概要 + 分群 + 完整獲得清單）
4. 官方機率表（101 筆，與獲得進度連動）
```

目標設定必須**緊貼遊戲視窗下方**——它和開跑是同一個動作的兩半。
統計面板放第三是因為它一開始是空的。

### 統計與結算

- **統計面板**三層：概要（抽了幾次 / 花了多少 / 目標進度）＋ 分群命中數（依機率階層）＋ 完整獲得清單（可摺疊）。
- **結算畫面**（自動模式跑完）：達成 ✓ / 預算燒光 ✗、總抽數、總花費、獲得總覽。
  **不做**逐筆歷程——700 筆沒人會看。
- **官方機率表與獲得進度連動**：抽到過的標記出來（打勾 / ×N）。兩份資料本來就在同一個 key 上。
- **純 session**：重整即歸零，不寫 localStorage。理由：數字是假的，跨 session 累積「總花費」是假成就。

## 已知取捨（是決定，不是待辦）

1. **不做任何機率計算**。原本規劃的理論值、達成抽數分佈圖、運氣百分位**全部移除**。
   使用者的顧慮是「計算有機會出錯」。反駁過一次（容斥閉式可用蒙地卡羅交叉驗證消除誤算風險），
   使用者維持原判 → 尊重。**未來要加回來的話，驗證方法是：容斥閉式 vs 10 萬次蒙地卡羅，
   小數點後三位一致即可證明兩邊都對。**
   - 連帶：神秘任務只顯示「3/6 種橡皮擦」這類進度，**不回答「還要幾抽」**。
   - 參考數字（僅供開發者理解量級，**不要放進網站**）：集齊神秘任務期望值約 **700 抽 ≈ NT$12,600**。

2. **不寫免責聲明**（Q27=C）。但官方機率表旁的「活動期間 2026/08/20~09/10」標籤要保留——
   那是**資料標籤**不是免責聲明，多期結構下沒有它就分不出哪張表是哪期的。

3. **抓取靠手動觸發，且不掃描**（Q9/Q23 定案後再簡化）。
   已提議 GitHub Actions 每日自動掃描並被否決；後續連 ID 範圍掃描也拿掉，
   改成「使用者每期給活動網址」。失敗模式是永久且無聲的，見本檔開頭警告。

4. **UI 不做期數切換器**（Q24=B）。資料結構已按多期設計，但只有一期時切換器沒東西可切。
   有第二期再加，是零風險的加法。

5. **只做轉蛋機，不做其他活動**。同一支 API 底下的「皇家美容院」（49 列）、
   「閃亮彗星」（98 列）也有機率表、也會過期消失，但這期先不碰。
